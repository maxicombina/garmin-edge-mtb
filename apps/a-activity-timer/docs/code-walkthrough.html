Cómo funciona a-activity-timer

Un campo de datos que muestra el tiempo de actividad y adapta el formato al tamaño de la celda. Acá está el código y el flujo, explicados paso a paso.

formato compuesto

El modelo mental: dos funciones

Todo campo de datos vive de dos funciones que hacen cosas distintas y separadas a propósito. Entender esta división es la mitad del proyecto.

corre ~1×/s

compute(info)

Calcula. Recibe Activity.Info (la foto de los datos), lee el timer, arma los textos y los guarda en variables. No dibuja nada.

cuando hay que repintar

onUpdate(dc)

Dibuja. Recibe un Dc (el lienzo de tu celda), elige fuente según el espacio y pinta lo que compute() preparó. No calcula.

la analogía

compute() es quien lee el sensor y anota el número en un papel una vez por segundo. onUpdate() es quien agarra ese papel y lo pinta lindo cuando toca refrescar. El pintor nunca calcula; el que calcula nunca pinta.

Como no hay orden garantizado entre las dos (ni garantía de que compute() corra antes del primer onUpdate()), todo se inicializa en initialize() y el primer dibujo muestra 0:00 sin romperse.

El flujo de datos

De punta a punta, una vuelta del ciclo:

sistemallama compute(info) una vez por segundo — con los datos de la actividad
↓
compute()lee info.timerTime, lo parte en H/M/S y arma los textos + plantillas
↓
variablesquedan guardados mValueLong, mValueShort, mValueSup y sus plantillas — el "papel"
↓
sistemallama onUpdate(dc) cuando la pantalla se repinta (~1×/s si está visible)
↓
onUpdate()mide el espacio, elige nivel + fuente (con caché) y dibuja en la celda

Paso a paso: compute()

Corre una vez por segundo. Su trabajo es dejar los textos listos para dibujar.

  1. Leer el timer, a prueba de null

    timerTime viene en milisegundos y es Number or Null: antes de arrancar la actividad es null. La variable local t "estrecha" el tipo para poder asignarlo.

    function compute(info as Activity.Info) as Void {
    var ms = 0;
    // null before the activity starts
    if (info has :timerTime) {
        var t = info.timerTime;
        if (t != null) { ms = t; }
    }
    mTimerState = (info has :timerState) ? info.timerState : null;
    updateFromMillis(ms);
}

  2. Partir en horas / minutos / segundos

    División entera (trunca): el segundo 59 se muestra hasta que se cumple el 60 — igual que el campo nativo. timerTime ya se congela solo en pausa, así que no hay estado que mantener.

    var totalS  = totalMs / 1000;   // trunca
var hours   = totalS / 3600;
var minutes = (totalS % 3600) / 60;
var seconds = totalS % 60;

  3. Armar los textos

    Con horas se arman tres candidatos; sin horas, solo M:SS. La elección final de cuál usar es de onUpdate(), que es quien conoce la celda.

    if (mHasHours) {
    mValueLong  = Lang.format("$1$:$2$:$3$", [hours, mm2, ss2]);  // H:MM:SS
    mValueShort = Lang.format("$1$:$2$", [hours, mm2]);         // H:MM
    mValueSup   = ":" + ss2;                                 // :SS
} else {
    mValueLong  = Lang.format("$1$:$2$", [minutes, ss2]);       // M:SS
    mValueShort = mValueLong;
}

  4. Armar las plantillas de ancho estable

    Junto a cada texto se guarda una plantilla con los dígitos como 8. Es la clave del anti-parpadeo — se explica abajo.

El truco anti-parpadeo: las plantillas

La fuente se elige midiendo el texto. Pero si midiéramos el texto vivo, un valor con dígitos anchos podría entrar y otro no, y el formato saltaría de un segundo a otro. Solución: medir siempre una plantilla de ancho fijo (todos los dígitos como 8).

se mide esto
8:88:88

La plantilla solo cambia cuando cambia el patrón de dígitos (aparecen horas, 9→10 h…), nunca por el tick de segundos.

no esto
1:11:11
1:44:44

Dos anchos distintos con el mismo formato → causarían parpadeo si se midieran directamente.

La plantilla se construye con eights(n), que devuelve una cadena de 8 con tantos dígitos como el número — así 10:23 mide como 88:88 sin contar caracteres a mano.

Paso a paso: onUpdate()

Recibe el dc (el lienzo, ya recortado a tu celda). dc.getWidth()/getHeight() dan el tamaño de esta celda — la base de todo lo adaptativo.

  1. Colores según tema y estado

    getBackgroundColor() dice si el fondo es blanco o negro (tema del usuario). Si el timer no está ON, el valor se atenúa a gris pausa — se ve de un vistazo que no corre.

    1:23:45fondo blanco · corriendo
    1:23:45fondo negro · corriendo
    1:23:45pausado · atenuado

  2. Label opcional

    Si la celda es lo bastante alta (h ≥ 60 px), dibuja el label (Timer / Tiempo según el idioma) arriba en fuente chica. En celdas bajas se omite para dejarle todo el espacio al número.

  3. Elegir nivel + fuente (con caché)

    Solo recalcula si cambió el tamaño de celda o el patrón de dígitos. En un tick normal de segundos, onUpdate() no mide nada: reutiliza lo cacheado.

  4. Dibujar

    Una sola pieza (drawText centrado) para los formatos simples, o dos piezas para el compuesto.

La decisión de formato: 3 niveles

Hay una escalera de 8 fuentes (de mayor a menor); las 4 primeras son numéricas (diseñadas para valores de campo, legibles con guantes). Para <1h siempre es M:SS. Para ≥1h, el criterio es el ancho de la celda:

1:23:45

Nivel 1 · celda ancha
H:MM:SS uniforme (entra a lo ancho)

1:23:45

Nivel 2 · celda angosta
H:MM grande + :SS chico volado

1:23

Nivel 3 · muy angosta
H:MM pelado

bonus del nivel 2

El compuesto resuelve una ambigüedad: 1:23 a secas podría leerse como 1h23m o 1m23s. Con 1:23 grande + :45 chico, es inequívocamente 1h 23m 45s. Es la jerarquía inversa a la del 840 nativo (que vuela la hora chica); acá lo importante —H:MM— queda grande.

El render compuesto

El nivel 2 dibuja dos textos: el H:MM grande centrado verticalmente, y el :SS en una fuente chica alineada al techo del grande (superíndice). Las posiciones se calculan midiendo el ancho real con getTextWidthInPixels.

1:23:45
▸ pieza grande: TEXT_JUSTIFY_LEFT | VCENTER ▸ pieza chica: y = techo del grande ▸ separación: GAP_SUP = 2px

La fuente chica se elige como la más grande de la escalera que no supere ≈0.6× la altura de la grande — proporción constante, así se ve bien en cualquier celda.

La caché: cuándo se recalcula

Elegir fuente implica medir texto varias veces; hacerlo en cada repintado sería un desperdicio. La selección se guarda y solo se rehace cuando cambia algo real. La "llave" de la caché es:

(w, h, mTplLong, mTplShort)   // tamaño de celda + patrón de dígitos
  • Cambia el tamaño de celda (editás el layout en marcha) → recalcula.
  • Rollover 59:59 → 1:00:00 (aparece el formato largo) → la plantilla cambia → recalcula.
  • 9:59:59 → 10:00:00 o 9:59 → 10:00 (una plantilla se ensancha un dígito) → recalcula.
  • Tick normal de segundos → las plantillas no cambian → no recalcula.

Cómo lo probás en el simulador

Tu campo depende de Activity.Info, que en el simulador está vacío hasta que arrancás una actividad. Formas de probarlo sin salir a la calle:

  1. Ver el render adaptativo

    Cambiá el layout de campos del simulador (1 / 2 / 5 / 10) para ver el mismo valor en celdas de distinto tamaño y disparar los 3 niveles. No necesita datos de actividad.

  2. Ver el timer corriendo y cruzar la hora — TEST_MODE

    Poné TEST_MODE = true en los tunables de la vista: un reloj rápido suma 30 s de tiempo falso por segundo real, así ves el valor subir y cruzar 1:00:00 en ~2 minutos, pasando por todos los formatos. Dejalo en false para uso real.

    private const TEST_MODE = true;        // prende el reloj rápido
private const TEST_STEP_MS = 30000;   // +30 s por segundo

  3. Datos reales (tiempo real)

    Simulation → Activity Data → elegí Data simulation o un FIT/GPX Playable File, y apretá Start en el dispositivo. Antes de Start, timerTime es null y el campo muestra 0:00 atenuado — eso es la null-safety, no un bug.

  4. Medir para la tabla de la SPEC

    Un System.println(dc.getWidth() + "x" + dc.getHeight()) en onUpdate() imprime el tamaño de cada layout en la consola de VS Code — justo lo que la §11.1 pide anotar.
